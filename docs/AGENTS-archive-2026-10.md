# AGENTS.md — AIYA CMS（Headless 重构工作区）

本工作区正在把 AIYA CMS 从「单体 WordPress 主题」重构为「Headless WP 后端 + Astro 独立前端」。旧主题 `aiya-cms-wordpress-theme` 与旧前端 `aiya-astro-bulid` 已于 **2026-09-25 从工作区整体删除**，不再存在任何参考副本，不要试图打开或恢复这两个目录；所有 WP 侧代码在 `wp-content/plugins/aiya-core`（框架与业务域）与 `wp-content/plugins/aiya-publish`（外部发帖器 REST API），前端在 `front-station`，本地发帖器在 `publisher`（2026-09-08 拍板废弃旧前端 diff 路线，重写框架与 API client 直接对齐当前后台实现；迁移语义与历史拍板以本文件与 `aiya-core/docs/` 的记录为准）。

## 运行环境（Docker）

```bash
docker compose up -d                          # 启动
docker compose run --rm wpcli plugin list     # WP-CLI（entrypoint 已是 wp，直接跟子命令）
docker compose down                           # 停止（数据在命名卷中，不会丢）
```

- WordPress：http://localhost:8000（容器 `wp_app`，`wordpress:php8.5-apache`——运行时 PHP 8.5.10；镜像经 `docker.1ms.run` 转存拉取）
- Apache mod_remoteip：上游镜像默认信任全部内网段（`RemoteIPInternalProxy` 10/8、172.16/12、192.168/16、169.254/16、127/8）——内网直连进程发一个 `X-Forwarded-For` 即可无凭证伪造 `REMOTE_ADDR`、绕过 TrustedProxy 秘钥门（2026-10-01 审查实锤）。compose 已把 `docker/apache/remoteip.conf` 挂为容器 `/etc/apache2/conf-available/remoteip.conf` 覆盖为「不信任任何代理」：本地 XFF 一律不采信（头部原样透传给 PHP），真实访客 IP 由反代桥秘钥头恢复；**生产（nginx 反代）部署须替换该文件为仅信任 nginx 实际网段**（`RemoteIPInternalProxy <nginx网段>` + nginx 侧追加式 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for`），文件内注释含现成写法
- phpMyAdmin：http://localhost:8081（容器 `wp_pma`，root/rootpass）
- MariaDB 10.11（`wp_db`），库名 `wordpress`，连接信息见 compose 文件；OpenList（FileServe 域用）不在主 compose 内，独立运行于 `D:\TestAlist\docker-compose.yml`（:5244；配置/数据库在 `D:\TestAlist\data`，本地存储测试目录 `D:\TestAlist\local`→容器 `/opt/openlist/local`；WP 容器侧经 `http://host.docker.internal:5244` 访问，浏览器走 `http://localhost:5244`）
- `./wp-content` 挂载到 `/var/www/html/wp-content`，PHP 与插件的改动无需重建镜像；`wp_data` 卷中还有 WP 核心文件，插件 themes/plugins 请始终只改本地 `wp-content/`
- 涉及运行时验证（激活插件、看 REST 响应、清缓存）优先用 wp-cli 或 HTTP 请求，不要假设宿主机有 PHP/Node 环境可跑 WP

## 目标架构

```
Astro 前端 (front-station, SSR 模式保 SEO, node adapter; React 19 islands)
   │  仅消费版本化 REST API 的 JSON 形状（aiya/core/v1，由 aiya-core Api/Rest 提供）；
   │  类型化客户端镜像 Api/Contract 的 DTO（zod），不接触 WP_Post 原始结构；
   │  计数端点（like/view/rating）由浏览器直连 WP 以保留访客真实 IP 去重
   ▼
WordPress (Docker, 无头模式, 启用 aiya-headless 空壳主题)
   ├─ 内容 / 媒体 / 用户：WP 原生
   ├─ 设置 / 元数据 / 业务域 / Api 契约：aiya-core 插件（packages/ 承载基础设施包）
   └─ 旧主题遗产（模板、React 群岛、widgets、inc/* 函数、旧 REST aiya/v1）：已随迁移退役，代码仓 2026-09-25 删除
```

- 前端不加载 aiya-core 框架，不渲染 PHP；后端不为前端输出 HTML 片段（短代码类内容在 API 中给原始数据或规范化的结构，渲染归前端）。
- 不复用旧 REST 命名空间 `aiya/v1`，新 API 重新设计并带版本号；旧数据需要保留可读时，在 aiya-core 内做兼容读取层，不要在新 API 里泄漏旧字段形状。

## 重构原则

- 本项目是重构，不是移植：不要求也不建议复刻旧主题/旧框架的代码结构、类名、函数名与实现手法。旧代码的「怎么做」不是参考答案。
- 一律按 **WordPress 7.1 基准**与本地技能 `wp-plugin-development` 的现行做法实现（该技能面向 WP 7.0+）。旧实现中已过时的写法——全局函数拼装、`htmlspecialchars` 双重转义存储、自建静态缓存、外部 CDN 依赖等——明确不要照搬，新代码直接用 WP 现行 API。
- 旧主题与旧前端仓库已删除，其功能语义的迁移结论沉淀在本文件「迁移策略」与 `aiya-core/docs/MIGRATION.md`、`docs/ROADMAP.md` 的记录里；唯一仍然有效的旧契约是持久数据协议（数据库中的键名，见下节）——它在数据库里，与仓库删除无关。
- **契约优先**：Headless API 只输出 `src/Api/Contract/` 定义的 DTO（旧 `inc/core` 的 `*_In_While` 属性表是字段清单原型），禁止把 WP_Post / WP_Term 原始结构或 WP 数组形状泄漏给前端；旧对象里的展示逻辑（K 格式化、timeago、本地化兜底文案、HTML 构造器）一律剥离，归 Astro 侧。

## 通用守则

- 改插件前先加载本地技能 `wp-plugin-development`；安全要求（nonce、capability、sanitize/escape、`$wpdb->prepare`）按 WP 标准执行。
- 对 WP 核心 API 行为有疑问时，查 `wordpress-source/` 中的实际实现，不要凭印象写。
- 不修改 `wordpress-source/`；不把 `vendor/`、`node_modules/`、构建产物纳入版本管理。
- 新代码 PHP 侧统一 `declare(strict_types=1)` + `Aiya\Core\` 命名空间 + 4 空格缩进，与现有文件保持一致；文本域 `aiya-core`。
- 提交前自检：PHP 不读未定义数组 key；输出前 escape；新增设置字段有 label/默认值；不跨越上面表格中的目录边界。
